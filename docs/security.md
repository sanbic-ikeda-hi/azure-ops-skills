# 機密情報と権限

## GitHub に置くもの

スキル、スクリプト、秘密を含まないテンプレート、権限定義、テスト、一般的な手順だけを管理します。
実環境IDは秘密鍵ではありませんが、現物の値はリポジトリに埋め込まずPC側の接続プロファイルに置きます。

## GitHub に置かないもの

- 証明書の秘密鍵、PFX/P12/PEM/KEY、クライアントシークレット
- アクセストークン、更新トークン、認証コンテキスト、公開プロファイルXML
- 接続文字列、Functionキー、署名付きコールバックURL
- Azure の生レスポンス、実行履歴本文、アプリ設定値、実際の業務データ
- 管理者のサインイン情報、作業中のログ、ローカル接続プロファイル

.gitignore は誤登録対策であり、秘密情報漏洩を完全に検出・防止する仕組みではありません。
Test-Repository.ps1 のチェックも補助です。GitHubへの公開前には登録予定ファイルを確認します。
Privateリポジトリでも秘密鍵を保存しません。秘密をコミット済みの場合は、ファイルを後から除外するだけでは解消しません。
まず該当資格情報を失効・更新し、履歴への対応は別途承認して実施します。

## 認証

- 秘密鍵は Windows のユーザー証明書ストアに NonExportable で生成します。GitHubや復元用zipに移しません。
- 各PCには別の証明書を作成します。同じアプリに登録した証明書は、そのアプリに現在割り当てられた同じ権限を利用できます。
- 公開証明書のみを Entra に登録します。スクリプトはクライアントシークレットを生成しません。
- ユーザーの管理者操作と専用アプリの操作は分離し、Codex実行用処理は ServicePrincipal 接続だけを受け付けます。
- 証明書は登録したWindowsユーザーのCurrentUserストアで利用します。Codexの通常隔離環境が別ユーザーの場合、Azure操作は実行ツールの正規の承認付きでそのユーザー環境から実行します。Windows側の実行承認とAzure RBACの権限は別の制御です。詳細は [共通手順](change-workflow.md) に従います。
- Codex管理下のSandboxアカウントへ証明書を登録したり、証明書を見せるために秘密鍵ACLや隔離設定を緩めたりしません。証明書が見えない場合はwhoamiで実行主体を確認し、証明書の欠落と実行環境の違いを区別します。
- Scope Process / Disable-AzContextAutosave は今回のコンテキストの自動保存を抑止します。以前保存された資格情報やOSの認証キャッシュまで消す保証ではありません。
- 同じWindowsユーザーで動くプロセスからの秘密鍵利用まで防ぐ仕組みではありません。証明書の書き出し不可だけを完全な防御と扱いません。
- 証明書の有効期限と利用PCを管理し、期限前に更新します。PC廃止時は対応する公開証明書登録を1件だけ削除します。

## 権限

- 初期常設ロールは roles/services-reader.json の明示的な読み取り操作だけ。ワイルドカードは使用しません。
- 読み取りであってもキーや秘密情報を返すAPIがあります。すべての /read を無条件に許可しません。
- 詳細調査で不足する読み取りAPIは、その用途と戻り値を確認して追加案を出します。取得失敗を「未設定」に置き換えません。
- 変更権限は対象リソースIDに限定。削除、権限付与、ロック解除、管理者への自動切替は既定で許可しません。
- Azure RBAC の権限は合算されます。個別ロールの NotActions は、別ロールが与えた権限を打ち消す拒否規則ではありません。
- 作業終了・中断時には、その回に新規追加したロール割当だけを解除します。既存の読み取り割当や他作業の割当は削除しません。
- 権限付与・解除には反映待ちがあり、サインアウトだけでAzure側の割当が消えるわけではありません。
- 権限を付けた対象自体の誤設定はRBACだけでは防げません。変更差分・影響・戻し方の確認が必要です。
- リソースの変更権限から、実行コードやマネージドIDを通じて接続先へ影響する場合があります。接続先の権限と自動トリガーも変更計画に含めます。

## 現在の限定

付属ヘルパーはAzure Public Cloud / Windows / 1専用アプリ・1テナント向けです。Sandboxと必要なら本番の読み取りを設定でき、毎回対象IDを指定します。
一覧取得と基本メタデータを扱い、詳細ログ、秘密情報、業務データ、破壊操作は自動取得・実行しません。
実テナントでの検証結果は、ローカル構文・境界テストとは区別して記録してください。
