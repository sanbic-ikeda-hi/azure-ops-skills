# Azure Ops Skills

App Service / Functions / Logic Apps を、専用のエンタープライズアプリで扱う個人用スキル集です。

- 読み取り: 指定サブスクリプション内の対象3サービス。初期ロールには取得に必要な管理メタデータの読み取りだけを登録します。
- 変更: 承認したリソースIDだけに、その回に必要な操作を追加。サブスクリプション・リソースグループへの変更権限は通常要求しません。
- 新規: 既存・新規どちらのリソースグループも選択可。管理者向け作成コマンドを用意し、ユーザーが実行。作成後の個別リソースだけを専用アプリに許可します。
- 削除、ロール付与、ロック解除、管理者への認証切替はスキルから実行しません。PIM は使用しません。

## 初期設定

1. [Azure の準備](docs/setup.md)に従い、管理権限のあるユーザーが PowerShell で実行します。
2. 初期設定は専用アプリ・PC用証明書・読み取り専用カスタムロールを作ります。クライアントシークレットや変更権限は作りません。
3. 接続後に読み取りを確認し、ユーザー共通のスキル配置先にインストールします。

必要な情報は TenantId、SandboxSubscriptionId、必要ならProductionSubscriptionId。アプリ名の初期値は azure-ops-skills です。
GitHub のリポジトリURLは、push・別PCでのclone時に必要です。

~~~powershell
# このリポジトリのルートで実行（Azureに接続しないローカル検証）
pwsh -NoProfile -File .\scripts\Test-Repository.ps1

# 共通スキルの配置先を確認（書き込みなし）
pwsh -NoProfile -File .\scripts\Install-Skills.ps1 -WhatIf

# 内容を確認した後、ユーザー自身が配置する
pwsh -NoProfile -File .\scripts\Install-Skills.ps1
~~~

配置先は Windows ユーザーの .agents\skills です。実行時の認証設定は LOCALAPPDATA\AzureOpsSkills\connection.json を使います。
既存の同名スキルは自動上書きしません。更新は旧版との差分確認後、当該フォルダー内のファイルだけを反映してください。
リポジトリの編集中の変更は、配置済みスキルへ自動反映しません。

## Codexからの実行

ローカル作業は通常の隔離環境で行います。Azure操作は、既存のユーザー証明書を使えるWindowsユーザー環境で、実行ツールの正規の承認手続きを通して実行します。
別ユーザーの隔離環境と分かっている場合、最初から承認付き実行を要求します。Azureへの認証は専用アプリのままで、Sandboxアカウントへの証明書登録・秘密鍵の共有・Full Accessへの切り替えは行いません。
Windows側の実行承認と、Azure側で許可する操作は別です。初回作成と権限付与・解除はユーザー実行です。詳細は[共通認証手順](docs/authentication.md)を参照してください。

[Sandbox試験手順と結果](docs/sandbox-test.md)には、Logic Apps Consumption、既存プランへWeb Appを追加するApp Service、Functions Flex Consumptionの実地結果を記録しています。

## 対象選択と権限相談

「Functionsでordersに関係するアプリを探して、再起動に必要な権限を教えて」のように目的・サービス・キーワードを伝えます。
スキルが指定サブスクリプション内の候補を取得し、名前・リソースグループなどを番号付きで示します。対象を選んだ後、必要な操作・権限・影響を提案し、合意した内容の付与・解除コマンドを用意します。
目的や対象が既に明確なら、同じ質問を繰り返しません。候補選択と、権限付与・実操作の承認は区別します。付与・解除はユーザーが実行します。

一覧ヘルパーには任意の `-Keyword`（名前・RG名の部分一致）と `-ResourceGroupName`（RG名の完全一致）を追加しています。大文字小文字を区別せず、併用はAND条件です。
SKILLは `-OutputMode Summary -OutputPath <新規の絶対パス.txt>` を使い、既定20件の要約と整形済み全結果のファイルを併用します。SummaryでRGを指定するとRG単位で取得し、3サービスをまとめる依頼は `-Service All` で共通APIを重複取得しません。`TotalCount` は取得範囲内の絞り込み前、`Count` は一致件数、`ReturnedCount` は表示件数です。省略は `DisplayTruncated` で示し、取得完了の `Complete` と区別します。
`Get-InventoryReport.ps1 -Path <保存先.txt> -Skip 20 -Limit 20` で追加表示できます。Azure接続はなく、過去の取得時刻と `Source=SavedReport` を示します。変更前は対象を再取得します。既定のFullは従来の項目・全件出力・RGフィルター適用前のサブスクリプション単位件数を維持します。どのモードもタグや秘密設定を検索・出力しません。詳細は[共通手順](docs/change-workflow.md)を参照してください。

新規配布では、各スキルに共通参照2件（change-workflow.md、authentication.md）とヘルパー5件（Common.ps1、Authentication.ps1、Get-ServiceInventory.ps1、Get-InventoryReport.ps1、Get-AppServiceQuota.ps1）を同梱します。SKILL.mdを含め8件×3スキルの計24ファイルです。クォータ照会だけはユーザー実行専用です。
リソース作成は3サービスとも必須の対応用途として維持します。繰り返し使う手順と、再利用・検証に適した作成ヘルパーをスキルと一緒に管理します。今回の共通エラー診断は同梱済みのCommon.ps1へ追加し、案件固有の試験用作成・削除スクリプトとは分けています。汎用作成ヘルパー全般の実装・実機検証を完了したという意味ではありません。
既存配置を更新するときも、上記8ファイルの差分をスキルごとに確認します。Common.ps1だけを更新してAuthentication.ps1を欠落させないでください。共通参照はリポジトリのdocsから各スキルのreferencesへ配置します。既存スキルの自動上書きは行いません。

## 段階的な共通化

第1段階は認証の分離と一覧・検索の効率化です。認証関数の名前と呼び出し方を保ち、Common.ps1からAuthentication.ps1を読み込みます。認証専用SKILLは追加せず、詳細を共通参照へまとめます。

| 段階 | 対象 |
| --- | --- |
| 1 | 共通認証、RG単位検索、3サービス一括取得、要約・保存結果の再表示 |
| 2 | 必要箇所の詳細取得、起動・停止・再起動、有効化・無効化、限定設定の変更 |
| 3 | 既存プランへのWeb App追加、Functions Flex・Logic Apps Consumption作成の共通化 |
| 4 | 作成済みZIPの配置、App Serviceスロット作成・切替・切戻し |
| 5 | 秘密を含むアプリ設定・接続文字列の編集、対象と時間を限定した診断 |

第2段階以降は今回の実装対象外です。秘密設定の認証主体は第5段階で再検討します。共通化した操作は計画・直前照合・限定操作・GET検証・UTF-8記録を揃え、対応するOSやホスティング方式ごとに検証します。

## Microsoft製スキルとの連携

この3つをサービス別の入口にし、必要な場合だけ導入済みのMicrosoft製スキルを参照します。

| 入口 | 主な参照先 |
| --- | --- |
| azure-appservice | azure-diagnostics、App Service対応版のazure-reliability、azure-resource-lookup |
| azure-functions | azure-diagnostics、azure-reliability、azure-upgrade、azure-resource-lookup |
| azure-logicapps | azure-resource-lookup、Standardの基盤に適用できるazure-diagnosticsの手順、Logic Apps向けMicrosoft Learn |

依頼時は`$azure-appservice`、`$azure-functions`、`$azure-logicapps`のいずれかを入口にできます。Microsoft製スキルを単独で呼び出した場合に、本スキルの連携指示が自動適用されるとは扱いません。
Microsoft製は調査項目・評価方法・コマンド案を補います。実行時の認証、対象IDの確認、個別リソースへの権限付与・解除、秘密情報の扱いは本スキルの運用方針に従います。
これは指示による連携であり、他スキルのコマンドを自動的に安全な接続で包む仕組みではありません。実際の操作権限はAzure RBACで制限します。
参照先のログイン、広いContributor権限、権限不足時の再試行をそのまま実行しません。Azure CLI・azd・MCPを使う場合も接続主体の照合が必要です。
診断に必要なStorageや監視ログの読み取り権限は、初期ロールに含まれていない場合があります。

Microsoft製スキルはこのリポジトリへ複製・同梱しません。別PCで未導入でも基本一覧は使え、詳細はMicrosoft Learnで補います。
デプロイ関連スキルの参照は、対象サービス・方式・準備済み計画などの前提が合う依頼に限ります。調査依頼から自動デプロイへ進めません。
