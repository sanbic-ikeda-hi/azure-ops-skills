# App Service の運用

## 必須環境と不足時の案内

- Windows、PowerShell 7.2以降。
- Azure PowerShell の Az.Accounts と Az.Resources。Azモジュール全体やAzure CLIは必須にしない。
- 専用アプリの接続プロファイルと、このWindowsユーザーの証明書ストアにある有効な秘密鍵付き証明書。

初回実行・別PCでの実行前に、次の読み取りだけの確認を行う。

~~~powershell
$PSVersionTable.PSVersion
Get-Module -ListAvailable Az.Accounts, Az.Resources | Select-Object Name, Version
~~~

不足がある場合は、その項目をユーザーへ伝えて停止する。Azモジュール未導入なら、PowerShell 7で次を実行するよう案内する。

~~~powershell
Install-PSResource -Name Az.Resources -Repository PSGallery -Scope CurrentUser
~~~

Az.Accountsは依存関係として導入される。モジュール導入後に両方の版を確認する。
インストール・更新・ダウングレード、実行ポリシー変更をCodexが勝手に行わない。
復元時は管理台帳のmodule-versions.jsonで記録した版を優先し、既存版を無断で置き換えない。
既存のコマンドとパラメーターは導入版を確認してから使う。認証設定がなければ初期設定手順をユーザーに案内する。

## 認証と対象

- Windows / PowerShell 7。インストール・認証方式・権限の変更はユーザーが行う。PIMは使用しない。
- 専用エンタープライズアプリで接続する。設定は LOCALAPPDATA\AzureOpsSkills\connection.json（許可サブスクリプション一覧とSandboxのIDを含む）、秘密鍵はWindowsユーザー証明書ストアにある。
- 管理者の保存済み接続にフォールバックしない。テナント、サブスクリプション、アプリIDと認証種別を照合する。
- 対象は今回の依頼または現在の案件で確認する。他案件の変更対象を引き継がない。読み取りでも対象サブスクリプションIDを明示する。
- テストにはローカル設定のsandboxSubscriptionIdを利用できる。本番に試験を向けない。試験構築も対象・費用・権限・接続先への影響を具体化し、削除や権限拡大の承認を省略しない。
- トークン、秘密鍵、接続文字列を表示・保存しない。生レスポンス、Debug、Transcriptで記録しない。

## Microsoft製スキルとの連携

このスキルをサービス別の入口とし、次の条件に合うときだけMicrosoft製スキルの技術手順を参照する。基本一覧の取得だけなら追加スキルは不要。

| 依頼 | 参照するMicrosoft製スキル | 適用範囲 |
| --- | --- | --- |
| 高CPU、遅延、起動失敗、TLSなどの障害調査 | `azure-diagnostics` | App Service向けの調査手順だけを読む |
| ゾーン冗長化、ヘルスチェック、障害時の切り替えの点検 | `azure-reliability` | 導入版がApp Serviceに対応している場合だけ使う。共有プランへの影響も確認する |
| タグ検索、対象サービスの棚卸し | `azure-resource-lookup` | 基本一覧は既存ヘルパーを優先し、追加検索の組み立てに使う。対象サブスクリプションを限定する |

### 参照から実行へ進む条件

1. 利用可能なスキル一覧から名前を照合し、表示された実際のSKILL.mdと必要な参照ファイルだけを読む。導入版の対応サービス・前提条件を確認し、使用したスキル名と版（なければ参照パス）を案件に記録する。Microsoft製の全文をこのスキルへ複製しない。
2. 未導入、未対応、必要なツールがない場合は明示し、Microsoft Learn MCPで技術手順を補う。依存スキル、Azure CLI、拡張機能などを自動インストール・更新しない。必須環境の不足や認証・権限エラーを別の認証で回避しない。
3. 参照先のスクリプトは、実行前にログイン、Azureへの書き込み、権限付与、削除、秘密値出力、自動再試行の有無を確認する。調査・設計の依頼では読み取りと提案までに留める。他スキルの参照は操作の許可を追加しない。
4. Azureへの実行には既存のPowerShellヘルパーとCommon.ps1の接続・照合処理を優先する。追加コマンドでも、実行前に専用アプリのID・認証種別・テナント・明示したサブスクリプションを照合し、変更先の完全なリソースIDを確認する。CLI・azd・MCPがPowerShellと同じ認証を使うとは仮定しない。そのツールの接続主体を照合できなければ実行せず、確認方法を案内する。別ツールのために秘密鍵を取り出さない。
5. 参照先が管理者ログインやContributorを前提としていても、同意済みの個別リソース権限の方針を維持する。不足する操作と対象IDを特定し、ユーザー向けの付与・解除コマンドを準備する。Storage・監視ログなどの追加読み取り権限も、現在のロールに含まれると仮定しない。参照先の自動修復・再試行を理由に、権限拡大や削除を行わない。
6. 新規作成や変更の案は、このスキルの「新規作成」「既存変更」の手順に戻してレビューする。初回作成は既存RG・新規RGのどちらでもユーザーが実行する。参照した手順が、対象・権限・秘密情報の制約と両立しなければ実行を止め、具体的な代替手順を示す。

デプロイの検証・実行手順が必要な依頼では、`azure-validate` / `azure-deploy`も参照できる。ただし、導入版が対象サービス・方式に対応し、準備済み計画などの前提を満たす場合に限る。実行にはユーザーの依頼範囲と上記の接続・権限確認が必要。前提がない通常の調査や新規作成を、自動で`azure-prepare`→検証→デプロイへ連鎖させない。未実施の検証をValidated扱いにしない。

## 読み取り

初回設定済みなら、対象サービスの全リソースを読み取り対象にできる。依頼された内容に必要な範囲を取得する。
ユーザー共通の配置済みスキルでは、このSKILL.mdの隣の scripts/Get-ServiceInventory.ps1 を使う。
ソースリポジトリで作業中はリポジトリ直下の scripts/Get-ServiceInventory.ps1 を使う。

~~~powershell
# <HELPER_PATH> は確認した絶対パスに置換する。現在の作業ディレクトリから推測しない。
pwsh -NoProfile -File '<HELPER_PATH>\Get-ServiceInventory.ps1' -Service AppService -SubscriptionId '<SUBSCRIPTION_ID>'
~~~

ヘルパーは一覧と基本メタデータのみ。詳細が必要なら、導入済みモジュールの版とMicrosoft LearnでAPI・必要権限を確認する。
読み取りロールには秘密を取得する操作を含めない。不足する権限は理由を添えてユーザーに案内し、自動追加しない。
取得日時・接続先・成功/未取得を分ける。失敗を「0件」「設定なし」に置き換えず、キャッシュやIaCを現在の実環境と扱わない。

## 既存変更

1. 完全なリソースID、現状、変更前後、影響、費用への影響、戻し方を準備する。
2. 必要なAPI操作を列挙したカスタムロールと、そのリソースだけへの割当コマンドを用意する。
3. ユーザーに「権限を付与できるアカウントでサインインし、このコマンドを実行」と案内する。
4. コマンドにはテナントID、サブスクリプションID、専用アプリのサービスプリンシパルObjectId、RoleId、完全なScopeを入れる。
5. サブスクリプション/RG全体の変更権限、Owner/Contributorへの丸ごとの昇格を通常の手順にしない。関係する別リソースは個別に案内する。
6. 権限反映後、専用アプリ接続で承認済み変更を適用し、実取得と動作で確認する。
7. 終了・中断時には今回新規追加した割当だけの解除コマンドを案内する。元の読み取り権限は残す。

削除、ロール割当の自動追加、ロック解除、管理者への自動認証切替はしない。
NotActionsは別ロールから与えられた権限を取り消すものではない。残存・継承された変更権限を確認する。
認証・権限・ネットワーク・環境の失敗時は止めて報告する。管理対象の設定変更を自動再試行しない。

## 新規作成

既存RG・新規RGともユーザー指定を尊重する。新規RGは必須にしない。
全作成リソースのIDと依存関係、同名の有無、費用、接続先への影響を先に確認する。
最初の作成は、ユーザーが実行する具体的なコマンド/IaCを準備する。同名があれば停止し、既存を上書きしない。
その後、新しく作った各リソースだけに必要権限を付けるコマンドを案内し、設定・配置・検証を専用アプリで進める。
作成権限と更新権限を区別できないAPIがある。RG全体の権限を「新規作成だけ」と説明しない。
What-if等は差分確認の補助であり、未評価項目や外部への副作用を完全に防ぐ保証ではない。

## このサービス固有の確認

Web App、スロット、App Serviceプラン、ランタイム、HTTPS、ネットワーク、認証、マネージドIDを対象にする。共有プランのSKUやスケールの変更は他のアプリへの影響を確認し、Web Appへの権限とプランへの権限を分ける。アプリ設定値、接続文字列、公開プロファイル、Kuduの認証情報を出力しない。

## 案件への記録

対象・変更案・IaC・結果は現在の案件に保存する。共通スキルのソースやGitには実環境の生データを入れない。
コード/ローカル検証、ユーザー提供の実行結果、独立したAzure実取得を分けて報告する。
初期版の認証・権限付与・Azure実取得は未検証。ローカルテストの成功だけで本番利用を検証済みとしない。
